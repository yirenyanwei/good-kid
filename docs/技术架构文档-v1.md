# 《好孩子》小程序 · 技术架构文档 v1.0

> 配套文档：docs/设计文档-v1.md v1.1（产品功能定义，含轻量化与乐趣机制）
> v1.1 变更：genQuiz 支持难度自适应；微练习默认值（count=10、错题 3 题起步）
> 技术基线：微信原生小程序 + TypeScript + 云开发 CloudBase

## 一、技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | 小程序原生 + TypeScript | 页面量 <15，原生最稳、包最小、无框架升级负担 |
| UI 组件库 | TDesign（腾讯官方） | 与微信风格一致、按需引入不影响包体 |
| 渲染增强 | Skyline 渲染引擎（worklet 动画） | 报词卡片翻转、答题动效流畅，渐进启用 |
| 状态管理 | 页面级 state + 自写轻量 user store（~50 行） | 规模小，拒绝过度设计 |
| 后端 | 微信云开发 CloudBase（云函数 + 云数据库 + 云存储 CDN） | 免域名备案、免运维；openid 免鉴权自动注入 |
| TTS | 微信同声传译插件（免费）；V2 英语真人音频走云存储 CDN | 报词零成本起步 |
| 变现 | 流量主：激励视频 + Banner + 插屏 | UV≥500 后开通 |
| 工程 | ESLint/Prettier + 云函数独立目录 + GitHub Actions JSON 校验 | 轻量 CI |

**登录鉴权**：无自建账号体系。`wx.cloud.callFunction` 调用时云函数经 `cloud.getWXContext()` 自动获得 openid，作为唯一用户标识。无需注册/登录/token。

## 二、系统架构（三层）

```
┌─ 小程序端 ──────────────────────────────┐
│ 主包(<1.5MB)：首页 / 我的 / 设置 / 周报    │
│ 分包 subject-zh / subject-math / subject-en│
│ 插件：同声传译(TTS) · 组件：激励视频/Banner │
└──────────── wx.cloud ─────────────────┘
┌─ 云开发 CloudBase ──────────────────────┐
│ 云数据库：词库/题库/错题/用户配置           │
│ 云函数：出题·判题·周报统计·用户配置          │
│ 云存储+CDN：英语发音音频(V2)/插画          │
│ 定时触发器：每晚 19:00 学习提醒            │
└──────────────────────────────────────┘
┌─ 内容生产侧（本地，不参与发布）────────────┐
│ 老师资料 CSV → 校对脚本 → JSON → CLI 导入  │
└──────────────────────────────────────┘
```

调用关系：小程序端 ⇄ `wx.cloud.callFunction` ⇄ 云函数 ⇄ 数据库/云存储。全部流量走云开发通道，**无需配置合法域名、无需备案**。

## 四、数据模型（云数据库集合）

```
db_hanzi          # 汉字库
  { _id, grade: 3, volume: '上'|'下', unit: 1, hanzi: '绒',
    pinyin: 'róng', polyphone?: ['zhàng'], freq: 5 }

db_word           # 英语单词库
  { _id, grade, volume, unit, word: 'pencil', meaning: '铅笔',
    phonetic: '/ˈpensl/', audioFileID? }

db_quiz_log       # 练习记录（三科共用）
  { _id, openid, subject: 'zh'|'math'|'en', mode: 'random'|'unit'|'challenge',
    questions: [qid], correct: 8, total: 10, duration: 320, ts }

db_wrong_book     # 错题本（三科共用）
  { _id, openid, subject, grade, itemRef: hanziId|wordId|mathExprHash,
    wrongCount: 2, lastWrongTs, mastered: false }

db_user_config    # 用户配置
  { _id, openid, grades: { zh: 3, math: 3, en: 3 },
    speed: 'normal', notifyEnabled: true, weightedQuiz: true }

db_dictate_flow   # 默写断点状态
  { _id, openid, subject, unit, progress: 5, ts }
```

设计要点：
- **三科统一题目抽象**：`{ subject, type, prompt, answer, extra }`，出题/判题/错题本一套代码
- 口算题无词库，按表达式哈希作 `itemRef` 直接可判重
- openid 自动注入，不存任何孩子个人信息
- 错题毕业规则：`wrongCount≥3` 后连对 2 次 → `mastered: true`

### 数据分发策略（代码本地、数据远程）

**平台红线**：代码（js/wxml/wxss）与框架配置（app.json/页面 json/project.config.json）**必须随包**，动态下发代码属封号级违规。可远程的是：业务配置、词库题库、媒体资源。

**词库不出现在前端**：出题在 genQuiz 云函数服务端完成（查库+加权抽样），网络只传本次 20 道题（几 KB）。词库 2MB 还是 200MB 前端无感，天然流量最优。

**远程配置 + 本地兜底**：

```
包内（~300KB 兜底）：data/fallback.json（默认年级一册字词）+ 配置默认值
云端（真源）：
  - 词库真源：云数据库 db_hanzi / db_word
  - 业务配置：云存储 config.json（功能开关/文案/参数），走 CDN
策略：启动即用本地兜底 → 后台拉 config.json 版本号 → 有更新则增量刷新缓存
收益：断网可用（审核安全）+ 冷启动 <1.5s + 词库改版不发版
```

## 五、云函数接口设计

### genQuiz —— 出题统一入口

```
入参：{ subject, grade, mode: 'random'|'unit'|'challenge'|'special',
       unit?, count, constraints? }
出参：{ quizId, questions: [{ type, prompt, answer, extra }] }
```

- 语文/英语：查 db_hanzi / db_word，按 mode 过滤；random 模式查询该用户 db_wrong_book 做加权抽样（错题权重 ×3）
- 数学：服务端纯计算生成。按年级取数值范围模板（三年级：万以内加减+表内乘除+混合），constraints 控制进位/退位/运算类型；保证无负数、除尽
- **难度自适应**（v1.1 新增）：入参可选 `adaptive: true` 时，基于该用户 db_quiz_log 近 3 次正确率动态调整出题参数——连对升难度（扩大数值范围/引入混合运算）、连错降难度（缩小范围/锁定单一运算），孩子始终在"够得着"的区间
- **微练习默认**：count 缺省 10；错题本仅 3 条时也生成重练卷（不足 10 题按实际数出）

### submitResult —— 判题入库

```
入参：{ quizId, answers: [{ qid, correct }] }
```

事务内：写 quiz_log → upsert wrong_book（错的 wrongCount+1；连对更新毕业计数）→ 返回汇总。

### weeklyReport / userConfig

常规聚合与 CRUD。

**推送（V2，暂不做）**：原计划的 19:00 提醒推送因订阅消息平台约束（一次授权仅可发一条，无法每晚推送）且产品定位为纯练习工具，V1 砍掉。V2 如需召回：练习结束页请求订阅授权 → 次晚定时触发器（cron 七段式 `0 0 19 * * * *`）推一条含续订入口的召回消息。届时注意：部署后需单独"上传触发器"、config.json 声明 `subscribeMessage.send` 权限。

## 六、前端关键实现

### 统一题目渲染骨架 quiz-runner

三科练习页共享组件，按 `type` 分发渲染器：

```
type: 'dictate'   → TTS 播报 + 进度卡 + 重听按钮（语文/英语默写）
type: 'input'     → 数字键盘 + 即时判题（数学口算）
type: 'choice'    → 四选一 + 选项乱序（看拼音选字）
```

### TTS 封装（utils/tts.ts）

- 同声传译插件 textToSpeech，队列化播报（当前词播完 → 间隔 → 下一词）
- 语速档位由插件参数映射；多音字播报串由出题结果的 `extra.speakText` 提供（"长——长短的长"），端上不做读音决策
- **配额策略**：插件语音合成为全程序共享配额（100 次/分钟、2 万次/天）。采用**进入默写页时预合成整组**（20 词一次性排入合成队列）+ 失败退避重试，避免逐词实时合成撞分钟级限流。日活上千后规划切换云开发 TTS API（按量计费，无分钟限流）

### 本地/云端可切换的 request 层（cloud-api.ts）

```typescript
interface QuizAPI {
  genQuiz(params): Promise<Quiz>;
  submitResult(r): Promise<Summary>;
}
// V0：LocalImpl（词库 from fallback.json、口算端上生成、错题本 storage）
// V1：CloudImpl（wx.cloud.callFunction）
```

这是"先本地验证、后切云端"降级路径的实现锚点：数据结构与云函数入参出参完全一致，切换只换实现类。

## 七、内容生产流水线

```
content/raw/*.csv（老师资料）
  → scripts/validate.ts   # 拼音格式/多音字标注/重复/缺列检查
  → scripts/convert.ts    # 生成 dist/*.json（结构化词条）
  → scripts/import.ts     # 写入云数据库 db_hanzi/db_word + 生成 fallback.json
```

词库与代码分离：教材改版、补词只重跑流水线，不发版。GitHub Actions 在 PR 时跑 validate 保证词库质量。

## 九、成本

| 阶段 | 月成本 |

## 十、风险与技术对策

| 风险 | 对策 |
|---|---|
| TTS 多音字读错 | 词库预标注 + 组词消歧串，校验脚本覆盖 |
| 同声传译插件限流（100 次/分钟全程序共享） | 进页预合成整组 + 队列退避；日活上千切云开发 TTS API |
| 订阅消息一次授权一条 | V1 已砍推送（定位纯工具）；V2 做召回时练习结束页请求授权 + 续订入口 |
| 教育类目审核口径不稳 | 首选「工具」类目提审（个人确定可选，也是个人虚拟支付开放类目） |
| 教材改版 | 数据流水线重跑即可 |
| 云开发政策变动 | request 层抽象已隔离，可迁自有服务 |
| 广告影响留存 | 主流程零广告铁律 + 广告位 ≤3 |
| 触发器部署后不生效（V2） | 部署云函数后需单独"上传触发器"，并声明 subscribeMessage.send 权限 |
