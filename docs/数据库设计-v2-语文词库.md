# 云数据库设计 v2 —— 语文词库（多组词随机报）

> 配套：docs/技术架构文档-v1.md 第四章（本次升级 db_hanzi 结构）
> 变更日期：2026-10-25
> 驱动需求：按生字表+语文园地全量入库；每字 3-5 组词随机报，加深组词记忆

## 一、集合结构

### db_hanzi（汉字库，本次升级）

```js
{
  _id: "zh-3-shang-u1-晨",        // 规则：zh-{grade}-{volume拼音}-u{unit}-{hanzi}
  grade: 3,                        // 年级
  volume: "上",                    // 学期
  unit: 1,                         // 单元 1-8
  hanzi: "晨",
  pinyin: "chén",                  // 单字注音（含声调）
  klass: 1,                        // 1=一类字(会写) 2=二类字(认读)
  source: "lesson",                // lesson=课文生字 garden=语文园地识字加油站
  words: ["早晨", "晨读", "清晨", "晨光"],  // 组词 3-5 个（每词必含目标字）
  // speakText 已废弃：报词文本运行时由 words 随机生成「X——{word}的X」
}
```

**设计决策**：
- `words[]` 数组取代单条 `speakText`：同一字每轮听写随机报不同组词，反复练一个字
  时孩子接触 3-5 个词语，强化组词记忆（用户核心诉求）
- `source` 区分课文/园地字：语文园地字（轴基础阁厘帕祥 / 申介绍宗旨占乏 /
  恒圣萌妥 / 螺蝌蚪蟹鲤鲫鲨 / 睁眨瞪瞅眶怒呆睹，共 33 字）正式入库，
  出题时不区分（都算一类字）
- 重复判定按**字**算：`itemRef` 即 `_id`（每字唯一），同一字无论报哪个组词，
  错题本/去重都指向同一条记录
- 组词校验规则：每个词必须包含目标字（显示标红逻辑依赖），长度 ≤6

## 二、数据规模（三上语文）

- 汉字：282 条（249 课文字 + 33 园地字），平均每字 3.9 个组词
- 单元分布：u1:33 u2:39 u3:26 u4:20 u5:29 u6:52 u7:44 u8:39
- 词语表：37 条
- 单条文档 <200B，整库 <100KB —— 云开发免费额度完全无压力

## 三、读写路径

```
出题 genQuiz：
  云数据库 db_hanzi.where({grade, volume, unit?}) → 加权抽样(count) →
  每字 words[] 随机选一个 → speakText = "字——词的字" → 返回题目
报词显示 dictate 页：
  speakText.split("——")[1] 去掉尾部「的字」→ 逐字渲染，目标字标红
错题提交 submitResult：
  按 itemRef（= _id）聚合，同一字报不同组词错 N 次都是同一条 wrongCount+N
```

## 四、导入操作

1. 云开发控制台 → 数据库 → 新建集合 `db_hanzi`（权限：仅创建者可读写，
   云函数用服务端调用不受权限影响）
2. 导入 `content/dist/db_hanzi.json`（282 条，_id 规则见上）
3. genQuiz 已有「云库优先、内置兜底」逻辑：冷启动先查 db_hanzi，查到走云库，
   查不到用内置 hanzi.js（同源数据）
